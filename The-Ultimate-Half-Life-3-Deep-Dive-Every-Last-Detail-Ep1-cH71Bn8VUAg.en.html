Overview

Episode 1 of Tyler McVicker’s “Every Last Detail” series sets up a multi-part chronology of HLX, the codename he identifies as Half-Life 3, drawn from Valve’s own public Source 2 builds and patches. The video argues that because Valve does not fork Source 2 per title, engine features developed for one game appear across Dota 2, Deadlock, Counter-Strike 2 and others, making patch comparison a viable way to observe internal projects. Roughly half the runtime is a dated timeline of HLX-related findings from 2019 to November 2025; the second half is a debunk section rejecting open-world, VR, voxel-destruction and day/night-cycle readings, with Tyler asserting that HLX is a non-VR, non-open-world, largely traditionally lit Half-Life game. Tyler presents the timeline as artifact-based but repeatedly hedges on inference, and offers no release date.

Source 2’s shared, non-forked engine model

  • Description: Source 2 began around 2009, near the time of Left 4 Dead 2, and evolved from what Tyler calls an unfinished mess partly to blame for Valve’s dark times into an easy-to-use engine. Valve does not fork Source 2 per project: engine code pulled to build any one game is the same across all titles, so a system built for Deadlock can be adopted by Dota with little work compared with porting between branches. The stated downside is that features built for an unannounced project are eventually folded into the base engine of shipped games.
  • Confidence: Speculation — Tyler’s characterization of Valve’s engineering practice; no document, branch listing, or artifact is cited for the no-fork claim.

Terminology primer: VData, FGD, I/O, schemas, hint nodes

  • Description: Tyler defines VData as designer-driven gameplay data that lets designers add or modify mechanics without code, noting that post-2021 Source 2 games are heavily VData-driven, including Aperture Desk Job, Counter-Strike 2, Deadlock and Dota in some instances. FGD (Forge Game Data) is a plain-text entity definition file used by modeldoc, the Pulse editor, VData and Hammer, listing available entities (NPC, item, weapon types, physics props) and their customizable flags. I/O are entity commands used by level designers as basic logic in the map editor. Schemas are class descriptions exposing systems, properties and tools in human-readable form. Hint nodes give NPCs location information for reacting to the environment.
  • Confidence: Fact — these are definitions of documented Source 2 tooling conventions, verifiable in shipped tools.
  • Category: Engine feature
  • Source: Source 2 tooling conventions as described by Tyler.
  • Earlier mentions: None identified in this video.
  • Verification: verified — the file types and concepts can be inspected in shipped Source 2 game tools.
